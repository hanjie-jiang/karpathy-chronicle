## 覆盖范围

抓取对象是 Karpathy 主页「帖子（Posts）」时间线，即他本人发出的原创帖与自我接续的连载（self-thread）。不含：

- **转帖（reposts）**——不是他自己的文字；
- **「回复」标签页里他回复别人的帖子**——那是另一条时间线（`/karpathy/with_replies`）。如果你要把「他回复别人」的那部分也收进来，需要再跑一轮，见文末「如何扩展」。

## 怎么抓的（可复核）

1. **枚举 ID**：用浏览器打开公开主页 `x.com/karpathy`（未登录、无需登录），沿时间线向下滚动，抓取每条帖子的 status ID；长列表是虚拟化的，所以按小步长（约 2000px）多次滚动、边滚边收集、按 ID 去重，直到时间戳越过 2020-11。
2. **时间戳**：不依赖页面上「11月2日」这种相对日期，而是由 status ID（snowflake）解码出精确 UTC 时间，再折算北京时间。这样可以避免跨年显示歧义。
3. **正文**：短帖（≤280 字符）走 X 的公开嵌入接口 `cdn.syndication.twimg.com/tweet-result`，取 `text` 原文并把 `t.co` 短链还原成真实 URL；长帖（note）在该接口里被截断，因此改走一条会真实渲染页面的读取通道，抓取页面里正文节点的原文，保留段落换行。
4. **校验**：对同一批 24 条长帖，用浏览器直接渲染 `x.com/karpathy/status/<id>` 后读取 `tweetText` 节点作为独立样本，与第 3 步的文本做相似度比对，结果 0.996–1.000（仅空白与链接呈现方式有差异）。这是目前对本存档正文保真度的实测上限，不是全文逐条人工校对。

**可复现性说明（2026-11-06 补记）**：上述抓取和校验所用的脚本（session 03 日志提到的 `fulltext.py` 等）没有保存在本工作区，所以无法直接重跑。复跑时需要按本节描述重写脚本。存档文本本身仍然可用；只是第 4 步的抽样比对目前无法在本地复现。

## 已知局限（请按此判断证据强度）

- **完整性是「时间线可见范围」的完整性，不是 X 数据库意义上的完整性。** 被作者删除、设为保护、或平台降权不显示在公开时间线的帖子，抓不到。本存档可以证明「列出来的这些他确实发过」，不能证明「他没发过别的」。
- **长帖正文来自第三方渲染通道**（`r.jina.ai`），不是从 X 自己的接口直出。已用浏览器直读样本交叉验证，但仍属二手转换；引用具体措辞前，建议点开 `原帖` 链接核对一次。
- **互动数（赞/评论）是 2026-11-06 抓取时的快照**，之后会变。
- **语言**：绝大多数为英文，保留原文，未翻译。
- **图片**：只记录媒体 URL 与数量，没有下载图片本体。
- **转帖与对他人的回复不在内**（见上）。

## 如何扩展

- 补「他回复别人」的部分：打开 `x.com/karpathy/with_replies` 重复第 1 步的枚举，再走第 3 步。
- 增量更新：从最新一条往回滚动到已知的最新 ID 即可，其余步骤相同。
- 想把长帖换成浏览器直读版本：按 ID 打开 `x.com/karpathy/status/<id>`，取 `[data-testid="tweetText"]` 的 `innerText`。

## 字段

`karpathy-x-posts.jsonl` 每行：

- `id` / `url`：帖子 ID 与原始链接
- `created_at_utc` / `created_at_cst` / `date_cst`：UTC 时间、北京时间、北京日期
- `year`：按北京时间归年
- `text`：正文（长帖为完整正文并保留段落）
- `text_source`：`syndication`（短帖接口原文）或 `rendered_full`（长帖渲染全文）
- `is_long_note`：是否为超过 280 字符的长帖
- `reply_to` / `quote_of`：接续的父帖 ID / 引用的帖子 ID
- `media` / `links`：图片 URL、正文里的外链
- `likes` / `replies`：赞数、评论数（抓取时快照）
